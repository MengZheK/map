# 相册站点维护说明（maptool + GitHub）

本文档说明如何用桌面工具 **maptool** 增减照片，以及如何把变更提交到 GitHub、自动发布站点。

---

## 一键启动 maptool（Windows）

| 方式 | 说明 |
|------|------|
| **双击** 仓库根目录下的 `Start-Maptool.bat` | 首次会自动执行 `maptool` 内的 `npm install`，然后启动 Electron 开发模式。 |
| **桌面快捷方式** | 双击根目录下的 `Create-Maptool-Desktop-Shortcut.vbs`，会在桌面生成 **「Kang Map 相册工具」**，以后从桌面一键打开。 |

手动命令等价于：

```bash
cd maptool
npm install    # 仅首次或依赖变更后
npm run dev
```

关闭 Electron 窗口即退出。

---

## maptool 做什么

- 读写网站工程里的 **`public/photos/photos.json`**（合并写入，不删已有条目；保存前会备份 `photos.json.bak`）。
- 从本地照片读取 EXIF / GPS（多种格式；解析失败可手填）。
- 分类 ID、描述等可在工具里编辑；分类列表本地保存在用户目录的 `maptool-categories.json`。

详细行为见 **`maptool/README.md`**。

---

## 更新照片后的发布流程

1. 用 **maptool** 保存好 `photos.json`，并把新照片放到 **`public/photos/`**（与 JSON 里 `src` 路径一致，一般为 `/photos/pXXXX.jpg` 对应文件 `public/photos/pXXXX.jpg`）。
2. 在仓库根目录 **提交并推送**（见下一节）。
3. GitHub Actions（`.github/workflows/deploy-pages.yml`）会在推送 **`main`** 后自动执行 **`npm ci` + `npm run build`**，把 **`dist`** 部署到 GitHub Pages（含自定义域名 **map.robotedu.cc**）。

无需手动上传 `dist`，除非改为纯手动部署。

## 本地常用 Git 命令（提交到 GitHub）

在 **`d:\Kang\map`**（或你的克隆路径）打开终端：

```powershell
git status
git add public/photos/ docs/
git commit -m "相册：新增/更新若干照片"
git push origin main
```

若提示 **需要先拉取远程**：

```powershell
git pull --rebase origin main
# 如有冲突，解决后：
git add .
git rebase --continue
git push origin main
```

**建议**：改相册前先 `git pull`，减少冲突。

## 站点路径说明（避免白屏）

当前 **`vite.config.ts`** 里生产环境 **`base: "/"`**，适用于 **自定义域名根路径**（如 `https://map.robotedu.cc/`）。

若将来改为只使用 **`https://用户名.github.io/仓库名/`** 子路径部署，需要把 `base` 改回 **`/仓库名/`**，并同步路由 basename（参见仓库历史或咨询开发者）。不要混用未对齐的 `base` 与托管方式。

## 可考虑的优化

### 相册与性能

- **图片体积**：大图可先压缩或转为 WebP（保留一份 JPG 备用亦可），减轻 Pages 流量与加载时间。
- **`photos.json`**：体积变大后，可考虑按分类拆分或懒加载列表（需改网站代码）。
- **备份**：maptool 会写 `photos.json.bak`；重要变更也可另外复制一份 JSON 到网盘。

### 仓库与协作

- **`.gitignore`**：确认勿提交 `.env.local`、本地密钥；天地图等密钥只用 **`VITE_*`** 环境变量在构建环境注入（若以后在 CI 里配）。
- **提交粒度**：照片与 JSON 可同一提交，便于回滚。

### maptool 自身

- 需要可分发的 exe 时，在 **`maptool`** 目录执行 **`npm run build`** 生成安装包（可按 electron-builder 等方案扩展，当前仓库以 `npm run dev` 为主）。

### CI 与 GitHub Secrets（地图底图）

线上地图使用 **天地图**，构建时必须注入密钥；未配置时会回退为 OpenStreetMap，与本地 `.env.local` 效果不一致。

在仓库 **Settings → Secrets and variables → Actions** 添加：

| Secret 名称 | 说明 |
|-------------|------|
| `VITE_TIANDITU_TK` | 天地图密钥（与本地 `.env.local` 中相同） |
| `VITE_WEB3FORMS_ACCESS_KEY` | （可选）联系页邮箱订阅 |

可选 **Variables**：`VITE_MAP_BASEMAP_THEME` = `light`（默认浅色银灰）或 `classic`（官方彩色天地图）。

保存后重新推送 `main` 或手动重跑 **Deploy to GitHub Pages** workflow。

### CI

- 已在 workflow 里使用 **`npm ci`** 与 Node 20；依赖升级后若构建失败，本地先 **`npm run build`** 复现再修复。
